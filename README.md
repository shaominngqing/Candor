# 余净（YuJing）

余净是一款“解释型”的 macOS 磁盘空间与应用卸载工具。它的核心不是扫描出最大的“垃圾”数字，而是让用户看懂每一类空间的来源、判断能否清理，并在操作前了解影响。

产品原则：**每一 GB 都有归属，每一次清理都有依据。**

## 当前实现（0.8）

- 通用空间账本：一级分类只保留应用本体、应用数据、个人文件、缓存与临时文件、废纸篓、系统保护和“尚未说明”，不预设用户职业。
- 自适应场景：根据实际文件识别照片视频、下载与安装包、邮件聊天、云盘、游戏、虚拟机、设计创作、开发环境、本地 AI 模型和设备备份；只有占用明显且有大项目可查看时才出现在首页。
- 明确对账：未完成扫描、无权限或暂时无法归因的容量只显示为“尚未说明”，不再伪装成“其他与系统”。
- 增量空间账本：首次递归建立“来源级”记录；以后优先复用未变化且未过期的目录，只重算变化来源。
- 断点续扫：扫描过程中持续保存已经完成的来源；应用退出或扫描中断后，下次从已有账本继续。
- 快速更新与深度校准：日常使用快速核对；需要修正长期缓存或排查差异时，用户可主动重新遍历全部来源。
- 首次权限准备：扫描开始前统一引导用户开启完整磁盘访问；未授权时只运行有限扫描，主动避开受保护目录，不在后台逐个弹权限。
- 大项目：同时展示文件和文件夹，覆盖隐藏目录、`~/Library`、SDK、模拟器、本地模型和由大量小文件构成的大目录。
- 按需下钻：大项目只在用户点开文件夹时分析下一层，始终按实际占用从大到小排列。
- 安全清理：进入页面时按需检查，并复用空间账本里的目录大小；通用规则覆盖旧日志和超过 30 天的安装包，专业规则按检测结果补充 `.cache`、Gradle、Xcode DerivedData 等候选。
- 应用卸载：支持拖入 `.app`，合并展示应用本体和关联资源，按完整占用排序；应用大小直接复用空间账本，避免重复遍历应用包。
- 待清理篮：跨页面统一复核，自动避免父目录和子项目重复计算。
- 所有操作只移到废纸篓；界面明确说明只有清空废纸篓后空间才真正释放。
- Quick Look、Finder 定位、风险分级、路径白名单和运行中应用保护。
- 完全本地运行，不联网、不上传扫描结果。

## 页面结构

1. 空间账本：回答“空间都是什么”。
2. 大项目：回答“最大内容在哪里”。
3. 安全清理：回答“哪些有依据地可以处理”。
4. 应用卸载：回答“应用及其关联文件如何完整移除”。

旧的空间地图、独立大文件、独立缓存、独立残留、系统状态和安全说明页面已经移除，相关有效能力被合并到上述四条主流程。

## 运行

```bash
swift run YuJing
```

生成可双击应用：

```bash
./Scripts/build-app.sh
open "dist/余净.app"
```

当前构建使用临时签名，仅用于本机测试。正式分发需要 Developer ID、Hardened Runtime 与公证。

## 测试

```bash
swift test
```

测试覆盖关联文件匹配、删除路径边界、通用磁盘分类、十类使用场景、隐藏目录下钻、来源缓存复用、过期重扫、断点序列化和重建型缓存白名单。

## 当前边界

- 默认引导用户开启 Full Disk Access；若用户选择有限扫描，受 macOS 保护的目录会计入“尚未说明”，不会猜测内容。
- 完整磁盘访问必须由用户在系统设置中主动开启；余净不能也不会通过代码绕过 macOS 授权。
- APFS 克隆、快照和共享数据可能让目录合计与物理占用存在差异；差异继续保留为未说明，不冒充可清理空间。
- 快速更新使用来源目录修改时间和分级过期时间判断是否复用；目录深层变化最迟会在来源过期后重算，用户也可随时运行“深度校准”。
- 系统和共享目录只读展示，不提供直接删除。
- SDK、模拟器、本地模型和聊天资料以“核对/在对应工具中管理”为主，不默认选择。
- 不永久删除、不自动清空废纸篓、不关闭 SIP，也不执行不透明的清理脚本。
