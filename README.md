# Candor

Candor 是一款“解释型”的 macOS 磁盘空间与应用卸载工具。它的核心不是扫描出最大的“垃圾”数字，而是让用户看懂每一类空间的来源、判断能否清理，并在操作前了解影响。

产品原则：**每一 GB 都有归属，每一次清理都有依据。**

## 当前实现（0.12）

- 原生界面：页面收敛为 macOS 标准的 GroupBox、List、Section、工具栏和菜单，不使用卡片墙或装饰性仪表盘。
- 清晰对账：明确区分“已分类 + 未归类 = 已使用”；清理候选属于已分类空间，不与磁盘占用重复相加。
- 差额说明：未归类空间可以查看权限、扫描状态和 APFS 动态空间等原因，再决定快速更新或深度校准。
- 风险与操作分离：风险只回答“删除后有什么影响”，统一为可直接清理、可再生成、可重新获取、可能含数据四级；能否选择、应进入下一层还是应在来源应用中管理，使用独立操作状态。
- 三档范围：低影响只选旧日志和临时状态，标准增加长期未使用的应用缓存，更多空间增加大型可重建缓存和可重新获取资源；敏感数据永不自动选择。
- 筛选与排除：支持按类型和等级筛选、逐项调整和持久排除；手动改变选择后明确显示为“自定义”。
- 保守推荐：可再生成不等于推荐立即删除；只有长期未更新且达到体积条件的缓存才会进入推荐档。
- 简化操作：大文件与目录使用原生箭头进入下一层；只有真正的 macOS 系统范围显示锁，其余不可直接选择的项目会明确显示下一步。
- 语义删除单元：Android NDK、Build Tools、SDK Platform、系统镜像、Sources 和 CMake 按完整版本识别；版本目录可整项处理，内部零散文件引导返回组件层，避免删坏工具链。
- 应用卸载：默认选择首个应用，列表明确显示应用本体大小，并区分同名应用的安装位置。
- 通用存储分类：一级分类只保留应用本体、应用数据、个人文件、缓存与临时文件、废纸篓、系统保护和“未归类”，不预设用户职业。
- 自适应场景：根据实际文件识别照片视频、下载与安装包、邮件聊天、云盘、游戏、虚拟机、设计创作、开发环境、本地 AI 模型和设备备份；只有占用明显且有大项目可查看时才出现在首页。
- 明确对账：未完成扫描、无权限或暂时无法归因的容量只显示为“未归类”，不再伪装成“其他与系统”。
- 增量空间账本：首次递归建立“来源级”记录；以后优先复用未变化且未过期的目录，只重算变化来源。
- 断点续扫：扫描过程中持续保存已经完成的来源；应用退出或扫描中断后，下次从已有账本继续。
- 快速更新与深度校准：日常使用快速核对；需要修正长期缓存或排查差异时，用户可主动重新遍历全部来源。
- 首次权限准备：扫描开始前统一引导用户开启完全磁盘访问权限；未授权时只运行有限扫描，主动避开受保护目录，不在后台逐个弹权限。
- 大项目：同时展示文件和文件夹，覆盖隐藏目录、`~/Library`、SDK、模拟器、本地模型和由大量小文件构成的大目录。
- 目录大小索引：首次递归扫描顺手记录超过 1 MB 的目录汇总，不保存全部文件清单；后续展开和清理检查直接复用。
- 快速下钻：大项目点开后只读取当前层，任意深度的目录优先读取账本大小；索引缺失的小目录才局部补算。
- 清理建议：存储分析后自动检查，并复用同一目录索引；通用规则覆盖旧日志和超过 90 天的安装包，专业规则按检测结果补充 `.cache`、Gradle、Xcode DerivedData 等候选。
- 局部更新：Candor 内部移动文件后，只重新扫描包含变更路径的来源；未变化来源继续复用。
- 即时切换：清理范围使用一次生成的选择快照，预先保存项目和容量，不再逐项刷新或反复汇总 800+ 条记录。
- 近线性去重：待清理篮通过祖先路径集合消除父子重复，工具栏只读取轻量计数，切换页面时不再执行全量路径互比。
- 扫描状态一致：存储、清理建议、大文件与应用卸载统一区分等待、分析中和结果就绪；首次扫描不再用 0 或“没有结果”代替尚未产生的数据，后台更新则继续展示上次结果。
- 影响预览：清理前说明所选内容能否重新生成、最大项目和使用影响；主按钮先进入检查确认，再移到废纸篓。
- 应用卸载：支持拖入 `.app`，合并展示应用本体和关联资源，按完整占用排序；应用大小直接复用空间账本，避免重复遍历应用包。
- 待清理篮：跨页面统一复核，自动避免父目录和子项目重复计算。
- 所有操作只移到废纸篓；界面明确说明只有清空废纸篓后空间才真正释放。
- Quick Look、Finder 定位、风险分级、路径白名单和运行中应用保护。
- 完全本地运行，不联网、不上传扫描结果。

## 页面结构

1. 存储：显示磁盘总量、分类、未归类差额和清理建议。
2. 大文件与目录：回答“最大内容在哪里”。
3. 清理建议：按力度和影响选择可以处理的内容。
4. 应用卸载：回答“应用及其关联文件如何完整移除”。

旧的空间地图、独立大文件、独立缓存、独立残留、系统状态和安全说明页面已经移除，相关有效能力被合并到上述四条主流程。

## 运行

```bash
swift run YuJing
```

生成可双击应用：

```bash
./Scripts/build-app.sh
open "dist/Candor.app"
```

当前构建使用临时签名，仅用于本机测试。正式分发需要 Developer ID、Hardened Runtime 与公证。

## 测试

```bash
swift test
```

测试覆盖关联文件匹配、删除路径边界、通用磁盘分类、十类使用场景、缓存推荐时间条件、隐藏目录下钻、来源缓存复用、过期重扫、断点序列化和重建型缓存白名单。

## 当前边界

- 默认引导用户开启 Full Disk Access；若用户选择有限扫描，受 macOS 保护的目录会计入“未归类”，不会猜测内容。
- 完全磁盘访问权限必须由用户在系统设置中主动开启；Candor 不能也不会通过代码绕过 macOS 授权。
- APFS 克隆、快照和共享数据可能让目录合计与物理占用存在差异；差异继续保留为未归类，不冒充清理建议。
- 快速更新使用来源目录修改时间和分级过期时间判断是否复用；目录深层变化最迟会在来源过期后重算，用户也可随时运行“深度校准”。
- 系统和共享目录只读展示，不提供直接删除。
- SDK、模拟器、本地模型和聊天资料以“核对/在对应工具中管理”为主，不默认选择。
- 不永久删除、不自动清空废纸篓、不关闭 SIP，也不执行不透明的清理脚本。
